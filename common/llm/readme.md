# `llm` — Provider Abstraction SSOT

> **SSOT Key**: `llm_provider_abstraction` | Implementation: `apps/backend/src/llm/`.

Owns the one model entry point (`extension/agent.py`), the errors of a model call, `estimate_tokens`, and the VCR recordings of the model calls. There is no per-user provider layer (#2953) and no other client: the old gateway client, the old streaming client and the input-keyed cassette tooling are deleted (#3153). The three model roles come from the environment (`LLM_LARGE_MODEL`, `LLM_SMALL_MODEL`, `LLM_MULTIMODAL_MODEL`), and `LLM_ENCRYPTION_KEYS` is gone.

## <a id="axes"></a>Roles and call sites

1. **Model role**: `large`, `small`, `multimodal`. Each role has its model id and reasoning effort from the infra2 SDK settings (`settings.to_llm_settings()`). The API has no model catalog and no model picker (`GET /llm/catalog` is deleted). The three defaults are the SDK values (`glm-5.3-flash` for each role, reasoning `high` for large and `low` for small and multimodal). Only production, development and test may set `LLM_LARGE_MODEL`, `LLM_SMALL_MODEL` or `LLM_MULTIMODAL_MODEL` to another value. `Bootloader._check_llm_roles` (`apps/backend/src/boot.py`) refuses the start in any other environment (staging, ci, preview, an unknown name) when a role differs from the SDK default. It also builds `LlmSettings` at start, so an empty provider, an empty role model or a bad base URL stops the start and not the first model call (a blank `LLM_*_MODEL` or `LLM_BASE_URL` variable now stops the whole backend, as a short `SECRET_KEY` does; before, only the AI features failed at their first call) (`tests/infra/test_boot.py`, `AC-llm.2953`).
2. **Call site**: `CallSite` in `agent.py` names each call (`reconciliation.semantic_score`, `advisor.chat`, `extraction.statement`, `extraction.classification`, `extraction.csv_mapping`); the SDK puts it on the telemetry as `infra.llm.call_site`. `advisor.chat` uses the `large` role, extraction of a statement the `multimodal` role, the others the `small` role.
3. **Stored configuration (no reader)**: the tables `llm_providers` and `llm_scene_bindings` hold no row on staging or production (checked 2026-11-24 on #2953) and no code reads them. Their ORM models and the enums `ProtocolFamily`, `Scene` and `ReasoningEffort` stay only until stage 3 of #2953 (owner-reserved) drops the tables.

## <a id="agent"></a>The model entry point (#3153)

`apps/backend/src/llm/extension/agent.py` is the one place that calls `infra2_sdk.runtime.create_llm_agent`. `complete_text(call_site, role, content, decoding=...)` returns the reply text; `async with stream_text(...) as pieces:` gives it in pieces and closes the stream at the end of the block. Both stream the reply, so `DecodingSpec.timeout` is the longest wait for the next chunk. `system` is the instruction of the call and `history` the earlier turns (`{"role": "user" | "assistant", "content": text}`), so a chat is one call. `stream_text` must be entered and left in one task (the SDK opens a cancel scope and a context token); a reader that may read and close in different tasks, such as a response body, uses `iterate_text`: one producer task owns the stream and a queue hands each piece to the reader. `CallSite` names each call site; the SDK puts it on the telemetry as `infra.llm.call_site`. The SDK owns the provider client, the retry of a model error before the first byte of the answer (`max_attempts`; a stream that fails after output has started is not retried), the redaction of an error and the `gen_ai.*` telemetry.

Facts measured against Z.AI that the entry point fixes: the SDK sends `DecodingSpec.max_tokens` as `max_completion_tokens`, which Z.AI ignores (a cap of 20 gave 504 tokens), so the entry point sends it as `max_tokens` in `extra_body` for the provider `zai` (another provider keeps the SDK field); a caller sets neither `thinking` nor `max_tokens` in `extra_body`; a reply without text is an error and not a second request (`retries=0`). The SDK sends no `reasoning_effort` when `DecodingSpec.thinking` is None (measured 2026-11-24): a call that needs an effort sets `thinking` (the advisor sets the effort of the large role). The provider comes from `settings.to_llm_settings()` only. No code reads `llm_providers` or `llm_scene_bindings`.

**Errors.** Each failure of a model call leaves the entry point as one `ModelCallFailed` (`src/llm/base/errors.py`, a `LLMError`, so it maps to HTTP) with a `kind`: `rate_limit` (429), `timeout` (504), `unavailable` (503), `rejected` (502), `usage_limit` (429), `not_configured` (503), `bad_reply` (502), `unclassified` (502). It is counted once in `finance.llm.call.failed{call_site, kind}`. `bad_reply` also covers a 200 answer with no text (empty content, no choices, reasoning only, cut by the token limit or the content filter). A bad LLM setting (empty base URL or model) is `not_configured`, as a missing key is. The summary holds at most 300 characters. An `unclassified` failure is logged as an ERROR (an actionable fault) and the others as a WARNING. The SDK keeps the class of a provider error and turns every other error into a bare `RuntimeError` without the cause, so a caller cannot tell a provider fault from a bug by its class: the entry point reads the class where the SDK kept it, the label of the redacted summary for an unusable reply, and marks the rest `unclassified`. A call site catches `ModelCallFailed` and nothing broader, and a failure is never turned into a value that looks like an answer: `ai_semantic_score` raises, and the matching keeps the algorithmic score and sets `ai_semantic_unavailable` in the breakdown. The entry point does not wrap its own argument errors, `CancelledError`, or the refusals of a test run. The test guard against external I/O inside an open transaction raises `UnexpectedExternalIO`, a `BaseException`, and records the violation; for a model call it also sees the open transaction of a parent task, so a call in a TaskGroup child is refused; its fixture fails the test at teardown unless the test took the record. Ruff selects `BLE`: a blind `except Exception` must re-raise or carry `# noqa: BLE001 - <reason>`; `per-file-ignores` lists the files that still hold one (the list only shrinks, `tests/tooling/test_blind_except_work_list.py`).

Moved call sites: `reconciliation.semantic_score`, `extraction.classification`, `extraction.csv_mapping`, `extraction.statement`, `advisor.chat`. A moved call site reads no user setting: it resolves no provider of a user, only the environment of the deployment. The advisor streams the large role through `iterate_text`; a stored scene binding changes nothing (`test_chat_stream_ignores_a_stored_scene_binding`). The extraction call keeps `model=` (a forced model name), sends the seed and `do_sample`, and maps the SDK error classes to `ExtractionError` kinds (`rate_limit`, `timeout`, `http_error`, `model_error`); the SDK retries a server error of the model once (`max_attempts=2`).

Tests: `apps/backend/tests/conftest.py` sets `pydantic_ai.models.ALLOW_MODEL_REQUESTS = False`, so no test reaches a provider, and its guard refuses a model call while an application transaction is open (it covers the entry point, because the SDK sends through `httpx2`). A test gives a fake model with `install_fake_model` (fixture `fake_llm`, `tests/_support/fake_llm.py`; a reply function cannot fail the test with `assert`: check what was sent), or replays a recording with `@pytest.mark.vcr` and the fixture `vcr_llm` (it fails without the marker). A recording answers only the request body that it was recorded for. Record again: `LLM_API_KEY=<key> pytest --record-mode=rewrite <test>`. Product code imports no fake model and no recorder, and only the entry point calls `create_llm_agent` (`tests/tooling/test_model_entry_point_boundary.py`). `vcr_llm` pins the default provider and models, and fails under `--disable-recording`. A fake model is more lenient than the wire: an empty reply returns the empty text, and an HTTP error class is not retried.


## <a id="recordings"></a>Recordings

A VCR recording (`tests/**/cassettes/<test>/<name>.yaml`, by `pytest-recording`) holds the model request and its answer for one test; the replay matches the method, the address and the JSON body of the request, so a changed prompt or decoding fails the test until `LLM_API_KEY=<key> pytest --record-mode=rewrite <test>` records it again. Record the minimum: one recording for each request shape that production sends (classification, advisor chat, extraction text, reconciliation score). Never hand-author a recording; a recording holds no key (the `authorization` header is redacted). Offline, `pytest --record-mode=none` passes with no key and no socket.

## <a id="readings-eval"></a>Readings graded field-accuracy eval + drift ratchet

`tests/fixtures/readings/<fingerprint>.json` holds the stored reply text of a model for one statement, and `tests/fixtures/readings/ground_truth/<fingerprint>.truth.json` holds its synthetic or strictly redacted ground truth (Decimal-exact amounts). They are frozen: they came from prompts that the code no longer sends, and no tool records them again. `tools/check_readings_eval.py` scores each reading against its truth and enforces raise-only per-case floors in `tests/fixtures/readings-eval-baseline.jsonl` plus the corpus size floor in `readings-corpus-count-baseline.json` (minimum matrix across `text` and `vision`). It does not call the model and it does not call the product parser: it protects the fixtures, the truth files and the normalisers of the eval from a hand edit that lowers a score, and it fails on a reading that has no truth file. A regression of the product code is caught by `apps/backend/tests/integration/test_statement_corpus_journeys.py`, which runs 10 of the readings through the extraction pipeline. Drift detection is bounded to the covered matrix, a single sample is only a point estimate, and live provider accuracy on unseen PDFs stays verified on Staging (`staging_gate` and `scheduled_audit`).
