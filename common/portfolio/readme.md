# `portfolio` — Investment Position Accounting

Owns position quantities, cost basis (`FIFO`/`LIFO`/`AVGCOST` via `InvestmentLot`), `ManagedPosition` (`orm/portfolio.py`), `InvestmentTransaction`, and `DividendIncome` (`apps/backend/src/portfolio/`). Composes `ledger.post_entry` for double-entry cash/P&L entries and `pricing.resolve` for market valuations (never stores market prices or FX rates directly).

## Services & Reconciliation

- **Write (`extension/accounting.py`)**: `InvestmentAccountingService` exposes `post_buy`, `post_sell`, `post_dividend` using `TradeOrder`, `TradeAccounts`, and `DividendEvent`, ensuring open quantity `>= 0` and deterministic `source_type=system` entries (`common/audit/readme.md#source-type-trust-hierarchy-provenance`).
- **Atomic -> Managed (`extension/positions.py`)**: Windowed latest `AtomicPosition` per `(asset_identifier, broker)` upserts `ACTIVE` `ManagedPosition` rows and marks absent holdings `DISPOSED` (never deleted). Historical `as_of_date` checks `acquisition_date <= as_of_date < disposal_date`.
- **One writer per field (#2920)**: the snapshot import (`reconcile_positions`) writes the quantity, the status and `latest_snapshot_date` of a `ManagedPosition`. Only `post_buy` and `post_sell` write `cost_basis`, lots and realized profit. A snapshot has a market value and no purchase cost, so `reconcile_positions` never writes `cost_basis`.
- **Cost without a purchase is empty (#2920)**: `ManagedPosition.cost_basis` is `NULL` until a purchase is recorded. `get_holdings` then returns `null` for `cost_basis`, `native_cost_basis`, `unrealized_pnl` and `unrealized_pnl_percent`. A holding at a past `as_of_date` takes its cost from the BUY and SELL rows of `InvestmentTransaction` dated on or before that date. `get_portfolio_summary` returns `null` cost and profit totals when one active position has no cost, and counts such positions in `positions_without_cost_count`. The performance schedule row and its `unrealized_pnl` total follow the same rule and add one note per position. The balance sheet market adjustment treats an empty cost as a ledger cost of zero.
- **Known limit until #2922 (#2920)**: `post_buy` and `post_sell` have no caller in production code, so only tests write `cost_basis`. The holdings loaders do not compare the recorded purchase quantity with the position quantity. A purchase that covers a part of an imported quantity would show a cost for the full quantity. #2922 must make the loaders return no cost unless the recorded open quantity covers the position quantity, and must add the failing test first. A snapshot in another currency than the recorded purchases relabels the cost with the snapshot currency; #2922 must handle that case in the same change.
- **Read (`extension/{holdings,allocation,performance,performance_report}.py`)**: Computes XIRR/TWR/MWR, dividend yield, allocation, and FX-converted P&L via `pricing` (`PricingError` on missing rates). `calculate_time_weighted_return` (`start_value == 0`) and `calculate_dividend_yield` (`current_value == 0`) raise `InsufficientDataError`. `build_investment_performance_report_schedule` computes all holdings, metrics, and allocations in the requested schedule presentation currency. Use `Decimal`, never `float`.
